## 6. 坐标和 topic

检测器打印：

```text
pelvis=(x,y,z) raw=(x,y,z)
```

- `raw`：MID360 局部坐标系。
- `raw` 已完成候选聚类和球心外推，但未做腰部 FK。
- `raw` 不包含 `base-y-bias`。
- `pelvis`：经过 MID360→pelvis、Kalman 和 bias 后发布。

`rt/ball_state` 使用 pelvis body frame：

- `+x`：机器人前方。
- `+y`：机器人左侧。
- `-y`：机器人右侧。
- `+z`：pelvis 上方。

三维距离：

```text
sqrt(x^2 + y^2 + z^2)
```

主要 topic：

| Topic | 含义 |
|---|---|
| `rt/lowstate` | Unitree 状态 |
| `rt/lowcmd` | Unitree 控制 |
| `rt/lidar_ball_state` | LiDAR 已变换到 pelvis 的球观测 |
| `rt/cam_ball_state` | 相机球观测，目前无相机 |
| `rt/ball_state` | fuser 最终输出，策略读取 |
| `rt/policy_bridge_state` | bridge→策略状态 |
| `rt/policy_bridge_cmd` | 策略→bridge 命令 |

`rt/lidar_ball_state` 虽然叫 lidar，但已经是 pelvis-frame，不是 MID360 raw frame。

## 8. 当前主要问题：MID360→pelvis 标定错误

已经确认不是简单的球识别错误：

- 点云里只有一个高反射候选簇。
- 移动球时检测坐标稳定变化。
- 但坐标方向和距离不符合实物位置。

实测和输出示例：

```text
实际球心：机器人右前方，pelvis 前方约 0.5 m
检测 pelvis x：约 1.28–1.43 m
检测 pelvis y：约 +0.46 m
```

球在右侧时 pelvis `y` 应为负，但输出为正。

最近实时样本：

```text
raw    = (+1.370, -0.472, -0.423)
pelvis = (+1.414, +0.469, -0.022)
```

分析：

- `raw.y=-0.472` 对应 MID360 右侧。
- 变换后成了 pelvis 正 y，左右方向翻转。
- x 从实物约 0.5 m 变为约 1.4 m。
- `center_offset=0.085 m` 只能影响约 8.5 cm，无法解释约 0.8 m 的误差。

最可信根因：

```text
MID360→pelvis 的固定旋转/平移外参与实机安装不一致。
```

相关代码：

- `onboard/perception/lidar/mid360_to_base.py`
- `compute_mid360_to_base_transform()`

暂时不要：

- 用大的 `base-y-bias` 修正。
- 用遥控器 ball y bias 修正旋转错误。
- 大幅减小 `center_offset` 来凑 x 值。
- 未验证就翻转矩阵某一行并投入真机。

## 9. 现有标定工具是否可复用

项目目前没有 LiDAR 球心外参标定工具。

- `base-y-bias` 只能修正 pelvis y。
- 遥控球 bias 也只修改 y。
- `camera/debug/target_extrinsics_eval.py` 监听 `rt/target_state`，是胸部相机/AprilTag 工具，不能直接用于 MID360 ball。
- Sensor Dashboard 的 Current Bias 只显示 target y 和 ball y。

建议新增：

```text
onboard/perception/lidar/lidar_calibration.yaml
onboard/perception/lidar/calibrate_ball_extrinsics.py
```

推荐标定模型：

```text
p_true_pelvis = R_corr @ p_raw_mid360 + t_corr
```

不要只在当前错误变换后随意增加平移。至少先确认当前运动学矩阵是否整体不匹配。

## 10. 下一步标定流程

1. 机器人 FixedPose，腰部接近零位，保持保护。
2. 球静止。
3. 用卷尺测量相对 **pelvis 地面投影** 的 x/y 和高度 z。
4. 每个位置同时记录：
   - 卷尺实测 `p_true=(x,y,z)`
   - 检测器 `raw=(x,y,z)`
   - 当前输出 `pelvis=(x,y,z)`
5. 至少采集 3 个不共线点，建议 6 个：

```text
中心前 0.5 m
右侧前 0.5 m
左侧前 0.5 m
右侧前 1.0 m
左侧前 1.0 m
中心前 1.5 m
```

验收标准：

- 球在右侧时 pelvis `y<0`。
- 球在左侧时 pelvis `y>0`。
- 0.5–1.5 m 范围内 x 误差小于约 5 cm。
- 静止球坐标标准差小于约 2 cm。
- 机器人不运动时不会跨簇跳变。

完成静态标定后，先做吊挂 FreeKick，不要直接落地测试。

## 11. FreeKick 操作和手动切换

当前 FSM 手动路径：

```text
Select → FixedPose
R1     → FreeKick
B      → LocoMode
Select → FixedPose
F1     → PassiveMode
F2     → terminate
```

当前已支持手动 `LocoMode ↔ FreeKick`，但没有“自动走到球前→踢球→自动回 LocoMode”的状态机。

吊挂测试建议：

1. 确认腰部三轴解锁。
2. 确认静止球坐标方向和距离正确。
3. `Select` 进入 FixedPose。
4. `R1` 进入 FreeKick。
5. 没有异常时完整保留 12.24 s 动作。
6. 异常时 `F1`，必要时 `F2`。

## 13. 其他已知问题

- LiDAR 检测器会周期性打印 `joint_age_s≈0.28–0.62s`。
- 此时 MID360→pelvis 使用上一帧腰部角。
- 先完成静态外参标定，再调查该问题。

- `Logger.close()` 才把帧数写回 JSON。
- 仅按 `Select` 回 FixedPose 不会关闭 logger。
- 最终测试结束建议 `F1 → F2`。

## 16. 推荐接手顺序
